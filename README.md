# dotctl

Данная утилита разрабатывается и служит для упращения настройки дотфайлов .dot
Т.К. В последнее времядовольно много конфигов с ними становится неудобно работать и переезжать с машины на машину.
Было принято решение создать данный инструмент.
Основывается на пакете Stow и python также используется библеотека tk для графики.
Тапки не кидать, конструктивную критику принимаю. С гитом не работал, считай мой первый реальный проект.

Скачать:
```sh
git clone https://github.com/DevilNotSaint/archdot.git
```
Установка зависимостей:
Требуется Tkinter (`python3-tk` в Ubuntu, `tk` в Arch).

```sh
# Ubuntu / Debian
sudo apt install python3 stow
# Arch
sudo pacman -S python stow
```

Перейти в папку:
```sh
cd ./archdot
```

Запуск CLI через в папке проекта:
```sh
python3 ./dotarch.py
```
Выбирать пункты можно стрелочками и вводом цифры соответствующей команде.

Графический интерфейс находится в [`gui`](gui/README.md):

```sh
python3 ~/.dotfiles/gui/app.py
```
Каждый пакет — отдельная папка,
содержимое которой повторяет структуру домашнего каталога:

```text
~/.dotfiles/
  dotctl.py
  bash/.bashrc
  yazi/.config/yazi/yazi.toml
```

Меню на русском языке: список и состояние пакетов, подключение всех или
выбранных пакетов, отключение ссылок, просмотр и удаление бэкапов,
проверка «Посмотреть, что изменится». Она показывает, какие ссылки будут созданы
и какие конфиги будут сохранены в бэкап, без изменения файлов.
Выбирайте пункты цифрами; несколько пакетов
или бэкапов можно выбрать номерами через пробел. `0` возвращает назад или
закрывает главное меню. Перед изменениями показывается план и запрашивается
подтверждение `[Y/n]`: Enter или `y` выполняет действие, `n` отменяет.
Это относится и к удалению бэкапов.

Каждый переход очищает экран терминала. Заголовок и пункты текущего меню
остаются сверху, результат, проверка или ошибка отображаются ниже.
Результат остаётся до нажатия Enter, после чего открывается главное меню.
Во вложенных меню сохраняются список выбора и путь к текущему разделу.
При перенаправлении вывода очистка отключается.

Пункт **10. Добавить пакет** создаёт пакет из существующего файла или каталога.
Введите имя, например `hypr`. Откроется файловый браузер в домашней папке,
включая скрытые файлы и папки. Выбирайте папки цифрами, чтобы открыть их,
а файл — чтобы добавить его. Например: `.config/` → `hypr/` → `hyprland.lua`.
Команда `s` выбирает всю текущую папку, `u` поднимает выше, `h` возвращает
в домашнюю папку, `0` отменяет выбор. `/hypr` фильтрует список по имени,
`/` сбрасывает фильтр; `>` и `<` переключают страницы длинного списка.
Ссылки и сам репозиторий скрыты из списка выбора.

При необходимости команда `m` позволяет ввести путь вручную: относительно
домашней папки, с `~/` или абсолютный. Перед созданием мастер покажет структуру:

```text
~/.dotfiles/hypr/
  .config/
    hypr/
      hyprland.lua
```

Если указать `.config/hypr`, скопируется вся папка вместе с вложенными модулями,
темами и другими файлами. Структура определяется расположением файла, а не его
именем или расширением; содержимое Lua не разбирается. Файлы, на которые конфиг
ссылается за пределами выбранной папки, автоматически не импортируются.

Исходные файлы остаются на месте. Затем выберите пункт 4 для подключения:
Stow создаст ссылки, а исходные конфиги получат суффикс `-backup`.
Если в мастере указать имя существующего пакета, он предложит подключить этот
пакет без повторного копирования. Удалять папку пакета перед подключением не нужно.
Существующие пакеты не перезаписываются; пути вне домашней папки, ссылки и
конфиги, уже принадлежащие другому пакету, не импортируются.
При использовании `--target` структура определяется относительно этого каталога.

По умолчанию пакеты берутся из папки, где находится `dotctl.py`, а конфиги
подключаются в домашний каталог. Для проверки меню с другим целевым каталогом:

```sh
python3 dotctl.py --target /tmp/dotctl-home
```

Каталог назначения должен существовать. Командный режим также доступен
из любого каталога:

```sh
python3 ~/.dotfiles/dotctl.py list
python3 ~/.dotfiles/dotctl.py status --all
python3 ~/.dotfiles/dotctl.py apply --all --dry-run
python3 ~/.dotfiles/dotctl.py apply --all
python3 ~/.dotfiles/dotctl.py apply bash yazi
python3 ~/.dotfiles/dotctl.py backups --all
python3 ~/.dotfiles/dotctl.py clean bash --dry-run
python3 ~/.dotfiles/dotctl.py clean bash --yes
python3 ~/.dotfiles/dotctl.py clean bash --file .bashrc --yes
python3 ~/.dotfiles/dotctl.py clean --all --yes
python3 ~/.dotfiles/dotctl.py remove yazi
python3 ~/.dotfiles/dotctl.py prune --all --dry-run
python3 ~/.dotfiles/dotctl.py prune --all --yes
```

`apply` переносит существующий конфиг в соседний файл с суффиксом `-backup`
(например, `~/.bashrc-backup`), затем вызывает Stow. Повторное подключение
не создаёт бэкап собственной ссылки. Существующий бэкап никогда не
перезаписывается: операция останавливается до изменения конфигов.
При ошибке подключения инструмент пытается вернуть перенесённые конфиги.

`remove` отключает ссылки выбранных пакетов, сохраняя бэкапы. Ссылки ищутся
по записанному в них пути, поэтому пакет или отдельный файл уже могут быть
удалены из репозитория. GNU Stow по-прежнему используется для подключения;
отключение удаляет сами ссылки без требования наличия исходного пакета.
Пустые родительские каталоги сохраняются.

Пункт **11. Удалить старые ссылки** (команда `prune`) позволяет выбрать пакеты
или убрать все ссылки на отсутствующие файлы. Рабочие ссылки сохраняются.
Перед удалением показывается список; командный режим требует `--yes`.
Сканируется каталог назначения без перехода по ссылкам на каталоги.
Обрабатываются только ссылки с соответствием `репозиторий/пакет/путь` →
`каталог назначения/путь`; чужие ссылки и файлы `-backup` не удаляются.
Репозиторий должен существовать; если он перемещён, для старых ссылок укажите
прежний путь через `--repo` (при необходимости создайте там пустой каталог).

Для восстановления
исходного конфига после отключения переместите его вручную:

```sh
mv ~/.bashrc-backup ~/.bashrc
```

`backups` и `clean` находят только соседние `-backup` для файлов выбранных
пакетов в текущем репозитории. Если файл убран из пакета, его старый бэкап
нужно обработать вручную. Удаление необратимо и требует `--yes`.
Каталоги с суффиксом `-backup` автоматически не удаляются.
Для одного конфига используйте `--file` с путём относительно домашнего каталога
(без суффикса `-backup`); параметр можно повторять.

Для другого расположения или безопасной проверки используйте существующий
тестовый каталог вместо домашнего:

```sh
mkdir -p /tmp/dotctl-home
python3 /mnt/e/Codex_project/dotfilesarch/dotctl.py \
  --repo /mnt/e/Codex_project/dotfilesarch --target /tmp/dotctl-home apply --all
```

`--dry-run` показывает запланированные действия без изменений; это локальная
проверка плана, а не запуск симуляции Stow. Инструмент отказывается заменять
каталоги, проходить через ссылки в родительских каталогах и работать с
пересекающимися пакетами. Используется `--no-folding`, чтобы `.config` оставался
обычным каталогом. Файлы в пакетах подключаются все, включая README и скрытые
файлы; кладите документацию вне пакетов. Ссылки внутри пакетов и пользовательские
правила `.stowrc` / `.stow-*-ignore` не поддерживаются.

Не запускайте одновременно с ручным Stow или другим менеджером конфигов.
При аварийном завершении проверьте конфиги и бэкапы перед ручным удалением
оставшейся папки `.dotctl.lock` в репозитории.
